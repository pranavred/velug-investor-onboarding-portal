# v0.2.0 verification

Date: October 21, 2026. Scope: the move from OpenAI to Anthropic Claude through the official SDK, with the evaluation publish step. Evidence below was produced locally on macOS with Node 22.23 and a local Redis; nothing here claims production accuracy or external verification.

## Offline gates

- `npm run test:unit`: 168 passed, 1 skipped (real Redis integration without `TEST_REDIS_URL`). Provider networking is forbidden by `tests/no-provider-network.mjs` for both `api.openai.com` and `api.anthropic.com`.
- `npm run typecheck`, `npm run lint`: clean. `npm run build` and the rendered-HTML check passed.
- `npm run verify:reference`: 52 immutable historical GPT-4.1 artifacts verified. `npm run verify:distribution`: tracked files only, no credential patterns, no personal paths. `npm run verify:licenses`: 261 locked packages reviewed; the new `@anthropic-ai/sdk` is Apache-2.0 and its `fast-sha256` dependency is Unlicense.

## Live smoke (3 paid dispatches)

One held-out subscription PDF through the dev server: Claude Opus 5.5 classified `subscription` with model-reported confidence 0.93 in 3.3 s; Claude Sonnet 5.5 extracted five fields with page numbers and verbatim quotes, including the page-two values, in 4.7 s; every quote matched the parsed PDF text. One explicit review-draft dispatch on Claude Opus 5.5 returned five grounded source ids in 2.5 s. Stage traces carried the provider request ids.

## Held-out evaluation

See `evaluations/current/report.json` and the in-app "Current pipeline evaluation" panel. Seven runner invocations were made on October 21, 2026, all on the same 17 fixtures (dataset `elmshore-text-evidence-v1`), each costing at most 34 dispatches. Runs a and b, before the publish-step fixes, scored identically to the published run. Run c was invalidated by the local per-clock-hour Redis budget (four 429 denials before dispatch), which led to the publish guard that now refuses such runs. Run d returned one null-valued non-essential key on the address PDF; that exposed the over-strict traceability rule corrected in the same release, and it would have scored 58/59 on precision. Run f was stopped as redundant after a script-only change. Run g, against the committed pipeline, is the published report: purpose and folder 17/17, expected-value recall 58/58, output precision 58/58, source correctness 57/57, case outcomes 11/11, exception detection 8/8, false clears 0/8; 33 dispatches, 75,816 tokens, model-reported confidence 0.72 to 0.95, classification 1.4 to 5.4 s and extraction 1.9 to 3.3 s per document. Model variance between runs was limited to the one null-valued extra key noted above. These are small authored text PDFs; they do not measure scans, languages, authenticity, calibration or production accuracy.

## Hosted embed

The same pipeline, mirrored into the Velug website behind its Vercel firewall quota, processed a held-out bank PDF on a preview deployment in 6.6 s (classification 3.0 s, extraction 2.6 s, 4 of 4 fields grounded).

## Not verified

Scanned PDFs or OCR, languages other than English, real investor documents, authenticity, calibration of model-reported confidence, draft quality, and any production hosting, WAF or shared-quota behaviour beyond the single preview check above.
